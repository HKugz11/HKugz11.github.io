Why self-hosted

Built around privacy, not the other way round.

Running your own server isn't a compromise — it's the feature. Here's what that gets you.

You own your data

Everything lives on your server. No company account, no cloud, no one else holding your conversations.

End-to-end encrypted DMs

Direct messages and group chats are encrypted in the browser, so the server stores only scrambled text. (It still relies on whoever runs the server being honest — see the straight-talk section below.)

No ads, no trackers

No analytics and no third-party scripts. Voice calls use a public Google STUN server to connect. Translation runs on your own machine.

Works everywhere

Installs on iPhone and Android from the browser, plus desktop apps for Windows, macOS and Linux.

Light and fast

One small Node.js server. It runs happily on a spare PC, a Raspberry Pi or a small VPS.

Open source

MIT licensed and readable end to end. Change it, fork it, or just see exactly what it does.

How it works

From zero to chatting in three steps.

No accounts with a company, no sign-up forms. If you can run a couple of commands, you can host it.

Run the server

Install Node.js, download the project, then npm install and npm start. That's the whole backend. Full step-by-step guide ↓

Share the address

Send friends the link (and the access code for Xenon). A tunnel service lets you share it without opening router ports.

Everyone joins

Open it in any browser, add it to the home screen on iPhone or Android, or use the desktop app.

Set it up

Host it yourself, step by step.

Plan on 30–60 minutes the first time. You don't have to be an expert — but you'd be running a service other people use, so do it with a parent or guardian's OK, and only for people who are 13 or older.

Heads up: the source code isn't public yet, so steps 3 and 4 are a preview for now. Steps 1, 2 and 5 you can already do.

You'll need

  • A computer that can stay on — an old laptop or mini PC is perfect
  • An internet connection
  • A free playit.gg account (an adult may need to help make it)
  • Optional: a free DuckDNS name, for a friendly address and a trusted HTTPS lock

You don't need

  • A paid server, a domain name, or a credit card
  • To open ports on your router
  • To be a programmer — just comfortable typing a few commands

  1. Get a computer running Linux (recommended)

    For a server that stays on, Ubuntu Server LTS is a great choice. LTS means “long-term support”: five years of free security updates. Just want to try it first? Skip this step — Windows and macOS run it fine on your own computer.

    Download Ubuntu Server LTS Install guide

  2. Install Node.js (LTS)

    Node.js is what runs the server. Pick the LTS version (18 or newer). Then open a terminal and check it worked:

    node --version

    You should see a version number like v22.x.x. If it says “not found”, close the terminal and open a new one.

    Node.js downloads What is LTS?

  3. Download the project

    Get the app you want from its source page (download the ZIP, or use git clone), unzip it, and open a terminal inside its server folder.

    Xenon source Iridium source

  4. Install and start it

    Run these in the server folder. The first command downloads what the server needs.

    Xenon

    npm install
npm run setup   # pick an access code
npm start

    Then open http://localhost:3000.

    Iridium

    npm install
npm start

    Then open http://localhost:3200.

    If the page loads, it's working — on your own computer. Next, let your friends in.

  5. Let friends join from anywhere

    A tunnel gives your server a public address without opening router ports:

    1. Make a free account at playit.gg and install their agent on the same computer.
    2. Choose Add Tunnel → type TCP → local address 127.0.0.1 → local port 3000 (Xenon) or 3200 (Iridium).
    3. playit shows you a public address. Send it to your friends — and the access code, for Xenon.
    4. For real visitor addresses, switch on PROXY protocol in the tunnel and set "trustProxyProtocol": true in config.json.

    Right now friends will open a long playit address, and browsers will warn that it isn't private. The next step fixes that for free.

    Open playit.gg Download the agent playit help

  6. A friendly address with a trusted lock (optional, recommended)

    Voice calls and “Add to Home Screen” need a certificate that browsers trust, and it also removes the “not private” warning. You can get both free with DuckDNS (a free name like yourname.duckdns.org) and Let's Encrypt (free certificates).

    1. Go to duckdns.org, sign in with one of their login options, and create a free name. Your token is shown at the top of the page — treat it like a password. Never post it or paste it into a chat.
    2. Find your playit tunnel's IPv4 address: in a terminal run nslookup your-tunnel-name.tun.ply.gg (use the name playit shows you) and look for an address like 203.0.113.5. If you only see a long address full of colons (IPv6), change the tunnel in playit to get an IPv4 one.
    3. Type that IPv4 address into the current ip box next to your name on DuckDNS and click update ip.
    4. On the server, inside the project's server folder, run the certificate script (Xenon). The email is only for renewal notices — use a parent's or a spare one.
    sudo DUCKDNS_SUB=yourname DUCKDNS_TOKEN=paste-your-token LE_EMAIL=you@example.com APP_DIR="$PWD" bash deploy/setup-letsencrypt.sh

    It gets the certificate, installs it, restarts Xenon, and renews itself automatically. Then share https://yourname.duckdns.org:PORT — the port is the one playit gave your tunnel. If playit ever gives you a new IP, update it on DuckDNS.

    Iridium: that script is Xenon's for now. For Iridium, npm run gen-cert makes a self-signed certificate (browsers will warn) until a matching script is added.

    Open DuckDNS How Let's Encrypt works

  7. Keep it running (Linux)

    So it starts by itself after a reboot, use the ready-made systemd service file in the project's deploy folder. Edit its User= and folder lines to match your setup, then:

    sudo cp xenon.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now xenon

    (For Iridium, use iridium.service and iridium.) To update later: download the new version, run npm install again, and sudo systemctl restart xenon.

  8. Make it safe (don't skip this)

    • Keep image uploads off. They're off by default. Nobody reviews uploaded images, and you'd be responsible for them.
    • Keep the access code private, and change it if it leaks.
    • Turn on school-hours closing (quietHours in config.json) so nobody uses it in class.
    • Check reports. Run node admin.js reports often, and ban or delete accounts that cause trouble.
    • 13 and older only. If you learn someone is younger, remove their account.
    • Read the responsible-use guide included in each project before you invite anyone.

Something not working?

“node” or “npm” isn't recognized

Close your terminal and open a new one after installing Node.js. If it still fails, reinstall the LTS version from nodejs.org.

The page works on my computer but not for friends

Check that the playit agent is running, that the tunnel's local port matches the app (3000 for Xenon, 3200 for Iridium), and that your friends are using the address playit gave you — not localhost.

“Port already in use”

Another copy is probably already running. Stop it, or change port in config.json (and the tunnel's local port to match).

My browser says the connection isn't private

That's normal with a self-made certificate. It's safe to continue for your own server; a trusted certificate (for example through a free DuckDNS name and Let's Encrypt) removes the warning.

Straight talk

What's protected — and what to know.

Privacy claims are only useful if they're accurate. Here's the plain version.

What's protected

  • DMs and group chats are encrypted in your browser. Someone who steals the server's data files can't read them.
  • No ads, analytics or trackers. (Voice calls use a public Google STUN server.)
  • Passwords are hashed, wrong-password guesses are locked out, and a bad message can't crash the server.
  • Safety tools built in: block, report, delete my account, an admin tool for the person running it, and optional school-hours closing.
  • Open source is coming. The code will be public so anyone can inspect it.

What to know

  • Encryption has limits. Whoever runs the server could read your DMs by changing the server's code, and you can't verify your friends' keys yet. Channels aren't encrypted at all — the operator can read them, and the app says so.
  • You're the operator. You're responsible for your server and what happens on it.
  • Made for small groups who already know each other, not public communities. Sign-up asks people to confirm they're 13 or older (that's a promise, not age verification), and younger kids shouldn't use it.
  • Iridium keeps status and posts in plain text on your server.

Each project ships with a plain-English responsible-use guide covering what the software is for, what it isn't for, and the moderation tools available to whoever runs it.

FAQ

Good questions.

Is it really free?

Yes. Both apps are MIT licensed. The only cost is hosting, and a spare computer works fine.

Do I need to be technical to run it?

A little — you install Node.js and run two commands. Friends joining need nothing at all; they just open a link.

Does it work on iPhone and Android?

Yes. Open it in Safari or Chrome and choose Add to Home Screen — it installs like an app. Xenon also has desktop apps for Windows, macOS and Linux.

Is it okay for teens?

It's designed for small groups of people who already know each other, with no public discovery or strangers. Whoever runs the server is responsible for it, and younger users should have a parent or guardian involved.

Does this website track me?

No. This page loads nothing from third parties — no analytics, no external fonts, no scripts from elsewhere.
